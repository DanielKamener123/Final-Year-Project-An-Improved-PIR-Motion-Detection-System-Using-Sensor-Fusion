QUESTIONS TO HAVE ANSWERS READY FOR
- "Stand still?" -> Motion-based by design; stationary detection is not a requirement.
- "Crouch / crawl?" -> Weaker PIR and smaller blob; expected harder (report 5.1.5).
- "Is this the report model?" -> Same method. The demo model is the deployment model,
  trained on all data including this site, with a raised z threshold, a PIR strong-signal
  override and a PIR-only backup model. The report evaluates the method on held-out data.
- "Live PIR lamp vs report baseline?" -> Live lamp uses the latest sample; the report
  uses any sample since the previous frame. The live lamp is the stricter of the two.
- "Why feature-level, not decision-level?" -> Decision-level is limited by the weakest
  sensor (Peli). A far, slow walker gives a weak PIR, so keep the information until the end.
- "Why gradient boosting?" -> Best on the validation data out of 6 classifiers x 7 windows;
  first-principles version matches scikit-learn exactly.
- "Why not 20 % at the high clutter site?" -> Wind and sun raise background sigma, weak
  far targets drop below z, Pd 94 %. False alarms were still -66 %.
- "Traffic behind the zone?" -> Known; trained to favour detection at 10 m over
  rejecting road movement.
- "What if a sensor dies?" -> PIR backup model takes over (only demo it if rehearsed).
- "Low contrast?" -> Fundamental limit: no contrast means nothing to measure (report 5.1.3).

DON'T
- Don't start with the hardest case. Don't fight a failed walk: say "far and slow is the
  known weak spot, that was my one late detection in the report" and repeat it once.
- Don't forget to put the threshold back to 0.20 V after the trade-off.
